# Install & operate Hermes Omniscience

> **Applies to:** Omniscience 1.0.0 · written at commit f2109ab
> **Revised:** 2026-11-11 · **Body hash:** 6ef3aaab





Metadata-only observability for [Hermes Agent](../README.md): Hermes' own observer hooks feed a
sanitized event stream into a local SQLite DB, which a separate viewer process renders as a live
graph and a deterministic replay. No cloud service, no LLM calls, metadata only (see
[SECURITY.md](SECURITY.md)).

* Plugin: the repo root (stdlib only — runs inside Hermes' Python).
* Viewer: `viewer/omniscience_viewer/` (FastAPI + uvicorn, which Hermes already ships).
* Web UI: `web/` (optional static build served by the viewer).

---

## Requirements

* Hermes Agent (verified against v0.23.0, git `2bd378ed1b`).
* A Python for the viewer that has `fastapi` + `uvicorn` (Hermes' environment has both — see D5/D3).
* `sqlite3` (CLI or the stdlib module) for inspecting the events DB; Node/npm only if you want the
  optional web bundle.
* The viewer needs a WebSocket library (`websockets` or `uvicorn[standard]`) to serve the live feed —
  without one, the top bar shows OFFLINE.

---

## Windows

Tested on Windows 11 (PowerShell):

```powershell
python -m venv .venv

```

Demo:

```powershell
python demo/synth.py demo.db
$env:PYTHONPATH="viewer"; python -m omniscience_viewer --db demo.db
```

Then open `http://127.0.0.1:8797`. The viewer needs a WebSocket library (`websockets` or

* `scripts/demo-home.sh` and `scripts/real-run.sh` are Linux-only.
* On Windows the `0600` file mode on `events.db` is not applied; the file's privacy depends on the
  folder's permissions.

## 1. Install the plugin

The plugin lives at the **repo root** (`plugin.yaml` + `__init__.py` + `schema.py`, `sanitize.py`,
`store.py`). Hermes discovers a plugin at `<HERMES_HOME>/plugins/<name>/` containing `plugin.yaml`,
so the install places that folder at `<HERMES_HOME>/plugins/omniscience/`. Hermes also supports a
repository **subdirectory** install (`owner/repo/path/to/plugin`); this repository keeps the plugin
at the root, so no subdirectory is used.

### Option A — from GitHub

```bash
hermes plugins install KeyArgo/hermes-omniscience --yes-deps --enable
```

Pin an auditable commit with `--ref <40-char sha>` if you want a fixed build. `--enable` skips the
enable prompt.

### Option B — local checkout via symlink (what the e2e scripts do)

```bash
git clone https://github.com/KeyArgo/hermes-omniscience
cd hermes-omniscience
ln -s "$(pwd)" "${HERMES_HOME:-$HOME/.hermes}/plugins/omniscience"
```

`scripts/demo-home.sh` does exactly this symlink into an isolated `$HOME` so you can test without
touching your real profile.

---

## 2. Enable

Plugins are opt-in; they must appear in `plugins.enabled`.

```bash
hermes plugins enable omniscience          # adds "omniscience" to plugins.enabled
hermes plugins list                        # confirm it shows as enabled
```

> In an isolated demo home this is handled for you: `config.yaml` already lists
> `plugins.enabled: [omniscience]` (generated by `scripts/demo-home.sh`).

---

## 3. Restart the gateway — ⚠ owner action

Every Hermes session (`hermes`, `hermes --tui`, the Desktop app, messaging, cron) runs inside **one
gateway per profile**, and that gateway discovers plugins **once at process start**. A plugin you
just enabled/disabled is **not picked up by a running gateway**.

> **You must restart the Hermes gateway for enable/disable to take effect — and this restart is an
> owner action. It is never done automatically by Omniscience or by installing/enabling the plugin.**
> Disrupting a live gateway could interrupt in-flight sessions, so it is left to the operator.

* If Hermes runs under a supervisor (systemd, the Desktop app, etc.), restart it there
  (e.g. `systemctl --user restart hermes` or relaunch the Desktop app).
* One-profile-at-a-time: enabling the plugin applies per profile; each profile has its own gateway
  and writes its own `<HERMES_HOME>/plugin-data/omniscience/events.db`.

---

## 4. Verify it is flowing

Run any Hermes turn that touches a tool or delegates work, then check the DB (read-only):

```bash
sqlite3 "${HERMES_HOME:-$HOME/.hermes}/plugin-data/omniscience/events.db" \
  "SELECT kind, COUNT(*) FROM events GROUP BY kind ORDER BY kind;"
```

Only sanitized **metadata** is stored — never prompts, assistant text, tool argument values, tool
results, headers, or credentials ([SECURITY.md](SECURITY.md)).

---

## 5. Run the viewer

The viewer is a **separate process**; if it is down the agent is completely unaffected
([ARCHITECTURE.md §1](ARCHITECTURE.md)).

Optional — build the web bundle once (the viewer then serves the graph UI from `web/dist`):

```bash
cd web && (npm ci || npm install) && npm run build   # -> web/dist
cd ..
```

Launch the viewer (it reads the events DB read-only and derives the DB path from `HERMES_HOME` or
`OMNISCIENCE_DB`, defaulting to `~/.hermes/plugin-data/omniscience/events.db`):

```bash
PYTHONPATH=viewer python -m omniscience_viewer
```

Useful flags (from `viewer/omniscience_viewer/__main__.py`):

| flag | meaning | default |
|---|---|---|
| `--db PATH` | events SQLite path | `OMNISCIENCE_DB` / `HERMES_HOME`/plugin-data/omniscience/events.db |
| `--host` | bind address | **`127.0.0.1`** |
| `--port` | bind port | `8797` |
| `--static DIR` | static dir to serve | `web/dist` if present |

Then open `http://127.0.0.1:8797`. The REST/WS API is under `/api/v1` (`/api/v1/health`,
`/api/v1/sessions`, `/api/v1/events`, `WS /api/v1/live`).

> **The viewer binds `127.0.0.1` on purpose.** It has no auth. Do not expose it beyond loopback
> unless you have your own access control — pass `--host` explicitly only once you have thought that
> through ([SECURITY.md](SECURITY.md)).

For the isolated demo DB:

```bash
PYTHONPATH=viewer OMNISCIENCE_DB="$PWD/.demo-home/plugin-data/omniscience/events.db" \
  python -m omniscience_viewer
```

## 6. Upgrade

```bash
hermes plugins install KeyArgo/hermes-omniscience --yes-deps --enable
# restart the gateway once (owner action)
```

The recording is kept: `events.db`, `prefs.json` and `usage.db` live under
`<HERMES_HOME>/plugin-data/omniscience/` and are not part of the plugin install. The version chip in
the viewer header, `python -m omniscience_viewer --version`, and `GET /api/v1/version` report the
build that is actually running. If the chip still shows the old build, reload the page; the page
also notices a changed build and offers a reload.

## 7. Uninstall & data removal

Follow these in order (matches [SECURITY.md §Uninstall](SECURITY.md)):

```bash
hermes plugins disable omniscience                 # drop it from plugins.enabled / unregister
# ⚠ restart the gateway now (owner action) so the running gateway stops loading the plugin
hermes plugins remove omniscience                  # remove the installed plugin directory
```

To delete all stored events, remove the `plugin-data/omniscience` folder inside your Hermes home
(usually `~/.hermes/plugin-data/omniscience`).

* If you installed via **Option B**, also delete the symlink you made:
  `rm "${HERMES_HOME:-$HOME/.hermes}/plugins/omniscience"`.
* Nothing else in your Hermes home is touched by Omniscience; removing `plugin-data/omniscience`
  deletes every event it ever recorded.
* Isolated demo homes are disposable: `rm -rf .demo-home` (or wherever `OMNI_DEMO_HOME` pointed).

## 8. e2e helper scripts

These are for testing/demo, and **never** operate on the real `~/.hermes` (`demo-home.sh` refuses any
`*/.hermes` target):

| script | what it does |
|---|---|
| `scripts/demo-home.sh` | creates an isolated Hermes home at `${OMNI_DEMO_HOME:-<repo>/.demo-home}` (config + `plugins/omniscience` symlink). Idempotent. |
| `scripts/real-run.sh` | `HERMES_HOME=<demo home> hermes -z "<prompt: one tool call + one delegate_task>"` under a 900 s timeout, then prints the events-DB summary and fails if any required kind (session.start, turn.start, llm.request, llm.response, tool.end, subagent.start) is missing. |
| `scripts/secret-scan.sh `<db>`` | greps an `events.db` for secret shapes from SECURITY.md; exit 1 on any hit. Wire it into your e2e gate. |

```bash
scripts/demo-home.sh
HERMES_HOME="$PWD/.demo-home"           # only if you drive hermes yourself
scripts/real-run.sh
scripts/secret-scan.sh .demo-home/plugin-data/omniscience/events.db
```

Run the lane tests with the repo venv:

```bash
../../.venv/bin/python -m pytest -q tests/e2e
```
